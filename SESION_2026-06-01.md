## Resumen ejecutivo

Sesión enfocada completamente en el módulo de **Rutas / Muelle / Conductor**. Se corrigieron bugs críticos de UX, se implementó el flujo completo de entrega parcial con detalle de referencias, y se normalizó la paleta de colores al modo día en el módulo del conductor.

## Arquitectura del flujo de rutas (estado final)

```
Admin crea ruta (ruta maestra + conductor + vehículo)
  → PROGRAMADO

Admin "Iniciar Cargue"
  → EN_CARGUE
  → Muelle: admin asigna bultos MANUALMENTE (ya no hay auto-asignación)
  → Admin escanea cada bulto → CARGADO

Admin "Salió"
  → EN_TRANSITO
  → Admin ve "🚛 En camino" (no puede marcar como entregada)

Conductor (app modo día, fondo blanco)
  → Ve lista de paradas con badge por estado
  → Por cada parada confirma: ENTREGADO / PARCIAL / RECHAZADO

  ENTREGADO: forma de pago + monto (ambos obligatorios)
  PARCIAL:   forma de pago + monto + observaciones + detalle de referencias (cantidad entregada/devuelta)
  RECHAZADO: observaciones OBLIGATORIAS + foto opcional (botón cámara directo)
             forma de pago y monto ocultos

  Timer de 30s: NO interrumpe al conductor si está en formulario

Conductor "Cerrar Ruta"
  → ENTREGADA

Admin "📋 Ver"
  → Modal modo día: status por PD, detalle PARCIAL por referencia,
    motivo RECHAZADO, botón "📷 Ver evidencia" (abre nueva pestaña)

Admin "💰 Planilla"
  → Resumen financiero: totales por forma de pago
  → Por parada: estado, monto, forma de pago, detalle PARCIAL, motivo RECHAZADO
  → Sin foto inline

Admin "Liquidar"
  → Requiere todas las paradas gestionadas
  → estado_financiero = LIQUIDADA
```

## Features implementadas

### 1. Entrega parcial con detalle de referencias
- Conductor ve ítems del pedido con cantidades editables
- Devuelto se calcula automático (pedido - entregado)
- Admin ve tabla REFERENCIA | PEDIDO | ENTREGADO | DEVUELTO en Planilla y modal Ver
- Validación: no puede confirmar PARCIAL sin devolución real ni sin observaciones

### 2. Modal "📋 Ver" enriquecido (admin)
- Status por PD: badge ENTREGADO/PARCIAL/RECHAZADO + color
- Bultos marcados individualmente (✓ entregado / ✗ rechazado)
- Detalle PARCIAL: grid de referencias
- Motivo RECHAZADO en texto
- Botón "📷 Ver evidencia fotográfica" → abre imagen en nueva pestaña (descargable)

### 3. Foto con cámara directa (conductor)
- Botón "📷 Tomar foto con la cámara" (oculta el input nativo)
- `capture="environment"` → cámara trasera en móvil
- Previsualización inmediata + botón "✕ Quitar foto"

### 4. Validaciones explícitas por campo
- Frontend: mensaje específico por campo faltante + foco automático
- Backend: `ValueError` con mensaje claro → HTTP 400 (nunca 500)
